## Measurement & validity

<a id="q01"></a>
### 1. Area and centroid of each polygon

`ST_Area, ST_Centroid, ::geography`  ·  returns **20** rows  ·  [`queries/01_area_and_centroid.sql`](queries/01_area_and_centroid.sql)

```sql
SELECT name,
       round((ST_Area(geom::geography) / 1e6)::numeric, 3) AS area_km2,
       ST_AsText(ST_Centroid(geom), 5)                      AS centroid
FROM sectors
ORDER BY name;
```

> Cast to geography for square metres on the ellipsoid. ST_Area on 4326 geometry returns square degrees.

<a id="q02"></a>
### 2. Distance from a point to every hospital (metres)

`ST_Distance, ST_MakePoint, ::geography`  ·  returns **8** rows  ·  [`queries/02_distance_to_point.sql`](queries/02_distance_to_point.sql)

```sql
SELECT name,
       round(ST_Distance(geom::geography,
                         ST_SetSRID(ST_MakePoint(73.05, 33.71), 4326)::geography)::numeric) AS dist_m
FROM facilities
WHERE type = 'hospital'
ORDER BY dist_m;
```

> geography distances are geodesic metres. Fine for reporting; use ST_DWithin for filtering.

<a id="q03"></a>
### 3. Length of each road in kilometres

`ST_Length, ::geography`  ·  returns **10** rows  ·  [`queries/03_line_length.sql`](queries/03_line_length.sql)

## Buffers & proximity

<a id="q05"></a>
### 5. 500 m buffer around every hospital

`ST_Buffer, ::geography, ::geometry`  ·  returns **8** rows  ·  [`queries/05_buffer.sql`](queries/05_buffer.sql)

```sql
SELECT id,
       name,
       ST_Buffer(geom::geography, 500)::geometry AS buffer_500m
FROM facilities

```

> Buffering geography takes metres. Cast back to geometry to store or map the result.

<a id="q06"></a>
### 6. Facilities within 1.5 km of a point

`ST_DWithin, ::geography`  ·  returns **3** rows  ·  [`queries/06_within_radius.sql`](queries/06_within_radius.sql)

```sql
SELECT name, type,
       round(ST_Distance(geom::geography,
                         ST_SetSRID(ST_MakePoint(73.05, 33.71), 4326)::geography)::numeric) AS dist_m
FROM facilities
WHERE ST_DWithin(geom::geography,
                 ST_SetSRID(ST_MakePoint(73.05, 33.71), 4326)::geography,
                 1500)
ORDER BY dist_m;
```

> ST_DWithin uses the spatial index; ST_Distance(...) < 1500 does not. Always prefer ST_DWithin.

<a id="q07"></a>
### 7. Sectors with no hospital within 1 km (service gaps)

`NOT EXISTS, ST_DWithin`  ·  returns **7** rows  ·  [`queries/07_sectors_without_hospital.sql`](queries/07_sectors_without_hospital.sql)

```sql
SELECT s.name
FROM sectors s
WHERE NOT EXISTS (
    SELECT 1
    FROM facilities f
    WHERE f.type = 'hospital'
      AND ST_DWithin(s.geom::geography, f.geom::geography, 1000)
)
ORDER BY s.name;
```

> Anti-join pattern. Distance is measured to the sector boundary, so a hospital inside the sector counts as 0 m.

## Spatial joins

<a id="q08"></a>
### 8. Count facilities per sector (point-in-polygon join)

`ST_Contains, LEFT JOIN, GROUP BY`  ·  returns **20** rows  ·  [`queries/08_point_in_polygon_counts.sql`](queries/08_point_in_polygon_counts.sql)

```sql
SELECT s.name,
       count(f.id) AS facilities
FROM sectors s
LEFT JOIN facilities f ON ST_Contains(s.geom, f.geom)
GROUP BY s.name
ORDER BY facilities DESC, s.name;
```

> LEFT JOIN keeps empty sectors (count = 0). ST_Contains ignores points exactly on a boundary; ST_Intersects would count them in both neighbours.

<a id="q09"></a>
### 9. Facility counts by type per sector (pivot with FILTER)

`ST_Contains, count(*) FILTER`  ·  returns **20** rows  ·  [`queries/09_pivot_counts_by_type.sql`](queries/09_pivot_counts_by_type.sql)

```sql
SELECT s.name,
       count(f.id) FILTER (WHERE f.type = 'hospital') AS hospitals,
       count(f.id) FILTER (WHERE f.type = 'school')   AS schools,
       count(f.id) FILTER (WHERE f.type = 'park')     AS parks,
       count(f.id) FILTER (WHERE f.type = 'market')   AS markets,
       count(f.id) FILTER (WHERE f.type = 'pharmacy') AS pharmacies
FROM sectors s
LEFT JOIN facilities f ON ST_Contains(s.geom, f.geom)
GROUP BY s.name
ORDER BY s.name;
```

> FILTER is a tidy alternative to SUM(CASE WHEN ...) for conditional counts.

<a id="q10"></a>
### 10. Road length inside each sector (line-polygon overlay)

`ST_Intersection, ST_CollectionExtract, ST_Length`  ·  returns **48** rows  ·  [`queries/10_road_length_per_sector.sql`](queries/10_road_length_per_sector.sql)

```sql
SELECT r.name AS road,
       s.name AS sector,
       round((ST_Length(ST_CollectionExtract(ST_Intersection(r.geom, s.geom), 2)::geography) / 1000)::numeric, 2) AS km_in_sector
FROM roads r
JOIN sectors s ON ST_Intersects(r.geom, s.geom)
ORDER BY r.name, s.name;
```

> ST_CollectionExtract(..., 2) keeps only the line parts, so stray touch points cannot break ST_Length.

<a id="q11"></a>
### 11. Neighbouring sectors that share an edge

`ST_Touches, ST_Intersection, ST_Dimension, array_agg`  ·  returns **20** rows  ·  [`queries/11_adjacent_sectors.sql`](queries/11_adjacent_sectors.sql)

```sql
SELECT a.name AS sector,
       array_agg(b.name ORDER BY b.name) AS neighbours
FROM sectors a
JOIN sectors b
  ON a.id <> b.id
 AND ST_Touches(a.geom, b.geom)
 AND ST_Dimension(ST_Intersection(a.geom, b.geom)) = 1
GROUP BY a.name
ORDER BY a.name;
```

> ST_Touches alone also returns diagonal (corner-only) neighbours. Requiring a 1-D intersection keeps edge neighbours only.

## Nearest neighbour (KNN)

<a id="q12"></a>
### 12. 5 nearest facilities to a point (KNN)

`<->, ST_Distance, LIMIT`  ·  returns **5** rows  ·  [`queries/12_k_nearest_facilities.sql`](queries/12_k_nearest_facilities.sql)

```sql
SELECT name, type,
       round(ST_Distance(geom::geography, 'SRID=4326;POINT(73.05 33.71)'::geography)::numeric) AS dist_m
FROM facilities
ORDER BY geom <-> 'SRID=4326;POINT(73.05 33.71)'::geometry
LIMIT 5;
```

> ORDER BY geom <-> point LIMIT k is index-assisted. On 4326 the operator ranks by degrees, which is fine at city scale; for wide areas over-fetch, then re-rank by geography distance.

<a id="q13"></a>
### 13. Nearest hospital for every school (KNN with LATERAL)

`CROSS JOIN LATERAL, <->, ST_Distance`  ·  returns **20** rows  ·  [`queries/13_nearest_hospital_per_school.sql`](queries/13_nearest_hospital_per_school.sql)

```sql
SELECT s.name AS school,
       h.name AS nearest_hospital,
       round(ST_Distance(s.geom::geography, h.geom::geography)::numeric) AS dist_m
FROM facilities s
CROSS JOIN LATERAL (
    SELECT name, geom
    FROM facilities
    WHERE type = 'hospital'
    ORDER BY geom <-> s.geom
    LIMIT 1
) h
WHERE s.type = 'school'
ORDER BY dist_m DESC;
```

> LATERAL runs the inner KNN query once per outer row, each using the spatial index.

<a id="q14"></a>
### 14. Nearest road to every market, with distance

`CROSS JOIN LATERAL, <->, ST_Distance`  ·  returns **10** rows  ·  [`queries/14_nearest_road_per_market.sql`](queries/14_nearest_road_per_market.sql)

```sql
SELECT m.name AS market,
       r.name AS nearest_road,
       round(ST_Distance(m.geom::geography, r.geom::geography)::numeric) AS dist_m
FROM facilities m
CROSS JOIN LATERAL (
    SELECT name, geom
    FROM roads
    ORDER BY geom <-> m.geom
    LIMIT 1
) r
WHERE m.type = 'market'
ORDER BY dist_m;
```

> KNN works for points against lines and polygons too, not just point-to-point.

## Clustering

<a id="q15"></a>
### 15. DBSCAN density clusters (400 m, min 4 points)

`ST_ClusterDBSCAN, ST_Transform`  ·  returns **60** rows  ·  [`queries/15_dbscan_clusters.sql`](queries/15_dbscan_clusters.sql)

```sql
SELECT id, name, type,
       ST_ClusterDBSCAN(ST_Transform(geom, 32643), 400, 4) OVER () AS cluster_id
FROM facilities
ORDER BY cluster_id NULLS LAST, id;
```

> eps is in CRS units, so project first (EPSG:32643 = UTM 43N, metres). cluster_id NULL means noise.

<a id="q16"></a>
### 16. K-means into 4 groups, with a centre per group

`ST_ClusterKMeans, ST_Collect, ST_Centroid`  ·  returns **4** rows  ·  [`queries/16_kmeans_clusters.sql`](queries/16_kmeans_clusters.sql)

```sql
WITH k AS (
    SELECT geom,
           ST_ClusterKMeans(ST_Transform(geom, 32643), 4) OVER () AS cid
    FROM facilities
)
SELECT cid,
       count(*)                                         AS n,
       ST_AsText(ST_Centroid(ST_Collect(geom)), 5)      AS centre
FROM k
GROUP BY cid
ORDER BY cid;
```

> Unlike DBSCAN, every point is assigned, and you choose k up front.

<a id="q17"></a>
### 17. Convex hull and area of each DBSCAN cluster

`ST_ClusterDBSCAN, ST_ConvexHull, ST_Collect`  ·  returns **3** rows  ·  [`queries/17_cluster_hulls.sql`](queries/17_cluster_hulls.sql)

```sql
WITH c AS (
    SELECT geom,
           ST_ClusterDBSCAN(ST_Transform(geom, 32643), 400, 4) OVER () AS cid
    FROM facilities
)
SELECT cid,
       count(*) AS n,
       round((ST_Area(ST_ConvexHull(ST_Collect(geom))::geography) / 10000)::numeric, 1) AS hull_ha,
       ST_ConvexHull(ST_Collect(geom)) AS hull
FROM c
WHERE cid IS NOT NULL
GROUP BY cid
ORDER BY cid;
```

> Turns point clusters into polygons you can map. Noise points (cluster_id NULL) are excluded.

## Tessellation & dissolve

<a id="q18"></a>
### 18. Hospital catchments with Voronoi polygons

`ST_VoronoiPolygons, ST_Dump, ST_Intersection, ST_Envelope`  ·  returns **8** rows  ·  [`queries/18_voronoi_catchments.sql`](queries/18_voronoi_catchments.sql)

```sql
WITH pts AS (
    SELECT ST_Collect(geom) AS g FROM facilities WHERE type = 'hospital'
),
study AS (
    SELECT ST_MakeEnvelope(72.986, 33.660, 73.096, 33.740, 4326) AS g
),
cells AS (
    SELECT (ST_Dump(ST_VoronoiPolygons(pts.g, 0, study.g))).geom AS cell
    FROM pts, study
)
SELECT h.name AS hospital,
       round((ST_Area(ST_Intersection(c.cell, study.g)::geography) / 1e6)::numeric, 3) AS catchment_km2,
       ST_Intersection(c.cell, study.g) AS catchment
FROM cells c
CROSS JOIN study
JOIN facilities h ON h.type = 'hospital' AND ST_Contains(c.cell, h.geom)
ORDER BY h.name;
```

> Each cell is the area closer to its hospital than to any other. Voronoi is planar, so this is an approximation in 4326 at city scale.

<a id="q19"></a>
### 19. Dissolve sectors into one polygon per series

`ST_Union, GROUP BY`  ·  returns **4** rows  ·  [`queries/19_dissolve_by_attribute.sql`](queries/19_dissolve_by_attribute.sql)

```sql
SELECT series,
       count(*) AS sectors,
       round((ST_Area(ST_Union(geom)::geography) / 1e6)::numeric, 2) AS area_km2,
       ST_Union(geom) AS geom
FROM sectors
GROUP BY series
ORDER BY series;
```

> ST_Union as an aggregate is PostGIS's dissolve. Shared edges disappear.

<a id="q20"></a>
### 20. Facility density on a ~1 km hexagon grid

`ST_HexagonGrid, ST_Intersects`  ·  returns **23** rows  ·  [`queries/20_hex_grid_density.sql`](queries/20_hex_grid_density.sql)

```sql
SELECT h.i, h.j,
       count(f.id) AS facilities,
       h.geom
FROM ST_HexagonGrid(0.01, ST_MakeEnvelope(72.986, 33.660, 73.096, 33.740, 4326)) AS h
JOIN facilities f ON ST_Intersects(h.geom, f.geom)
GROUP BY h.i, h.j, h.geom
ORDER BY facilities DESC, h.i, h.j;
```

> Requires PostGIS 3.1+. Size is in CRS units (degrees here). Inner join returns only occupied hexagons.
